# 게시글 CRUD 서비스 - Bad Prompt 실험

## 목적

최소한의 프롬프트로 개발했을 때 결과가 어떻게 달라지는지 비교한다.

이 실험에서는 **프롬프트 품질을 의도적으로 낮게 유지한다.**  
다만 비교 실험을 위해 각 기능을 **백엔드와 프론트로 분리**하여 요청한다.

이 문서는 **공통 프롬프트를 먼저 입력한 뒤**, 기능별 프롬프트를 순서대로 입력하는 방식으로 사용한다.

---

## 실험 의도

이 실험의 목적은 다음과 같다.

- 짧고 모호한 요청이 어떤 결과를 만드는지 확인한다
- 구체적인 제약 없이 요청했을 때 AI가 어떤 구조를 선택하는지 본다
- 동일한 기능을 구현하더라도 프롬프트 품질에 따라 결과가 얼마나 달라지는지 비교한다

---

## 공통 규칙

- 공통 프롬프트는 항상 먼저 사용한다
- 설계 요청은 하지 않는다
- 출력 형식은 강하게 제한하지 않는다
- 테스트 요구는 최소 수준으로 둔다
- AI가 질문하면 최소한으로만 답한다
- 추가 설명은 하지 않는다
- 각 기능은 순서대로 진행한다
- 프론트는 HTML, CSS, JavaScript로 구현하게 한다

---

## 실행 규칙

각 단계는 아래 순서로 진행한다.

1. 기능 요구사항 확인
2. 백엔드 프롬프트 입력
3. 프론트 프롬프트 입력
4. 결과 확인

이 실험에서는 프롬프트를 일부러 짧고 단순하게 유지한다.

---

## 1. 게시글 등록 구현

### 1-1. 기능 요구사항

- 사용자가 게시글을 등록할 수 있어야 한다
- 게시글 등록 API를 만든다
- 게시글 등록 화면도 함께 만든다

### 1-2. 백엔드 프롬프트

```text
게시글 등록 만들어줘.
작업이 끝나면 `D:\prompt-compare\prompt-Compare\boardPrompt\docs\results\ver01_bad.md`에에 사용한 API 경로와 request, response 예시를 JSON 형태로 알려줘.

```

### 1-3. 프론트 프롬프트

```text
게시글 등록 화면 만들어줘.
HTML, CSS, JavaScript로 만들어줘.
게시글 등록 API 호출도 연결해줘.
```

### 1-4. 결과 비교 포인트

- 게시글과 작성자 연결이 되는가
- 프론트 입력 폼이 최소 수준으로라도 동작하는가
- 등록 성공 후 처리 흐름이 있는가

## 7. Validation 추가

- 요청값 검증이 필요하다
- 게시글 등록/수정 등에 최소한의 검증을 넣는다
- 프론트에서도 기본 입력 검증을 할 수 있다

### 7-2. 백엔드 프롬프트

```text

```

### 7-3. 프론트 프롬프트

```text

```

- DTO validation이 적용되는가
- 예외 처리 응답이 일관적인가
- 프론트 입력 검증 메시지가 있는가
- 서버 검증과 프론트 검증이 어느 정도 맞물리는가

## 정리

이 문서는 **의도적으로 품질이 낮은 기능 프롬프트 실험용 문서**이다.

특징은 다음과 같다.

- 요청이 짧다
- 제약이 적다
- 구조 강제가 약하다
- 구현 디테일을 거의 주지 않는다

따라서 이 실험 결과는 이후의 **개선된 프롬프트 실험 결과와 비교하기 위한 기준점**으로 사용한다.
