
# 게시글 CRUD 서비스 - PRD + Bottom-Up + TDD 실험

## 목적

PRD 기반 개발에 **Bottom-Up 방식과 TDD(Test Driven Development)** 를 적용했을 때  
코드 품질과 구현 과정이 어떻게 달라지는지 비교한다.

이 실험에서는 기능을 한 번에 크게 구현하지 않고,  
작은 단위부터 아래에서 위로 쌓아 올리듯 구현한다.

또한 각 기능은 반드시 **테스트를 먼저 작성한 뒤 구현**해야 한다.

이 문서는 **공통 프롬프트를 먼저 입력한 뒤**, `PRD.md`를 함께 제공하고 사용한다.

---

# 개발 방식

Test Driven Development

Red → Green → Refactor

Bottom-Up Development

- 작은 기능 단위부터 구현
- 하위 책임을 먼저 안정화
- 테스트 가능한 단위부터 점진적으로 확장

---

# 개발 규칙

반드시 다음을 따른다.

1. 실패하는 테스트 작성  
2. 테스트 실행  
3. 최소 코드 구현  
4. Refactor  

Before writing code explain reasoning step by step.

출력 형식

1 Plan  
2 Tests  
3 Implementation  
4 Refactor  
5 Verification  

추가 규칙

- 기능 구현은 반드시 `PRD.md` 기준으로 수행한다
- 각 단계는 해당 기능 범위만 구현한다
- 테스트 없이 바로 구현하지 않는다
- 구현 후에는 테스트 결과를 기준으로 검증한다
- 작업이 끝나면 API endpoint와 request / response JSON 예시를 함께 정리한다
- 프론트는 HTML / CSS / JavaScript로 구현한다
- 프론트는 백엔드 API 연동 검증 중심으로 구현한다

---

# 실행 방식

각 기능은 다음 순서로 진행한다.

1. PRD 또는 기능 분석  
2. 백엔드 테스트 설계  
3. 실패하는 테스트 작성  
4. 최소 구현  
5. 리팩터링  
6. 프론트 연동 구현  
7. 결과 비교

# 1. PRD 분석

## 1-1 기능 요구사항

`PRD.md` 기반 TDD 개발 전략 작성

출력

- 구현 단계
- 테스트 전략
- 위험 요소

Scope

- 코드 작성 금지
- 분석과 전략 수립만 수행

---

## 1-2 백엔드 프롬프트

```text
PRD.md를 읽고 TDD 기반 개발 전략을 작성해줘.

다음을 포함해줘.
- 구현 단계를 어떤 순서로 나눌지
- 어떤 테스트를 먼저 작성할지
- 어떤 단위부터 Bottom-Up 방식으로 구현할지
- 예상되는 위험 요소

Scope
코드 작성 금지

출력은 다음 형식으로 해줘.
- 구현 단계
- 테스트 전략
- 위험 요소
```

---

## 1-3 프론트 프롬프트

```text
PRD.md를 읽고 프론트 구현 전략을 작성해줘.

다음을 포함해줘.
- 필요한 화면 목록
- 화면별 API 연동 순서
- 어떤 화면부터 구현하면 좋은지
- 백엔드 TDD 흐름에 맞춰 프론트는 어떤 순서로 붙이면 좋은지

Scope
코드 작성 금지
HTML, CSS, JavaScript 기준으로 분석만 해줘.
```

---

## 1-4 결과 비교 포인트

- PRD를 테스트 가능한 단위로 잘 쪼개는가
- Bottom-Up 순서를 합리적으로 잡는가
- 위험 요소를 현실적으로 식별하는가
- 프론트 연동 순서까지 고려하는가

# 정리

이 문서는 **PRD + Bottom-Up + TDD 기반 개발 실험용 프롬프트 문서**이다.

특징은 다음과 같다.

- PRD를 먼저 읽고 구현 전략을 세운다
- 기능을 작은 단위로 나눈다
- 반드시 실패 테스트부터 작성한다
- 최소 구현 후 리팩터링한다
- 백엔드 구현 과정을 테스트 중심으로 비교할 수 있다
- 프론트는 백엔드 API 연동 검증 중심으로 구현한다

이 실험은 단순 기능 구현 비교가 아니라,  
**개발 방법론이 결과물 품질에 미치는 영향**까지 비교하기 위한 실험이다.
