# 게시글 CRUD 서비스 - 구조화 프롬프트 실험 세트

## 목적
같은 프로젝트를 **기능 단위 + 명확한 제약 + 기대 산출물** 형태로 지시했을 때 품질이 어떻게 달라지는지 비교하기 위한 프롬프트 세트다.

## 공통 실험 조건
- 같은 초기 상태의 Spring Boot 프로젝트에서 시작한다.
- 초기 조건
  - Java 21
  - Spring Boot 3.x
  - Gradle
  - package: `com.example.board`
  - 의존성: Web, JPA, Validation, Security, MySQL Driver, Lombok, Test
- 공개 API
  - 게시글 목록 조회
  - 게시글 상세 조회
- 인증 필요 API
  - 게시글 등록
  - 게시글 수정
  - 게시글 삭제
- 로그인 성공 시 JWT를 발급한다.

## 사용 규칙
1. 아래 프롬프트를 **위에서부터 하나씩** 입력한다.
2. 한 단계가 끝나면 코드 반영 → 실행/빌드 확인 → 다음 단계로 진행한다.
3. 불필요한 대규모 리팩터링은 하지 않고, 해당 단계 범위만 구현하도록 유도한다.
4. AI가 애매한 부분을 물으면 이 문서에 없는 추가 요구는 주지 않고, 문서 범위 안에서 합리적으로 진행하게 한다.

## 1. 회원가입

```text
너는 시니어 Spring Boot 백엔드 개발자다.

현재 저장소는 Java 21, Spring Boot, Gradle 기반의 게시글 서비스 프로젝트다.
패키지 루트는 com.example.board 이다.

이번 단계 목표
- 회원가입 API만 구현한다.

요구사항
- 엔드포인트: POST /api/auth/signup
- 요청 필드: email, password, nickname
- 이메일 중복 검사를 수행한다.
- 비밀번호는 BCrypt로 암호화한다.
- 응답은 JSON으로 반환한다.
- controller / service / repository / domain / dto 구조를 유지한다.

작업 규칙
- 이번 단계에서는 로그인, JWT, 게시글 기능은 구현하지 마라.
- 필요한 파일만 생성 또는 수정해라.
- 기존 코드의 불필요한 리팩터링은 하지 마라.

출력 방식
1. 변경 계획을 5줄 이내로 요약
2. 코드 변경
3. 생성/수정 파일 목록
4. 내가 확인할 포인트
```

## 3. JWT 인증 적용

```text
너는 시니어 Spring Security 개발자다.

현재 저장소 기준으로 JWT 인증이 실제로 동작하도록 보안 구성을 완성해라.

요구사항
- 로그인 시 발급한 JWT를 이후 요청에서 사용할 수 있어야 한다.
- POST /api/posts, PUT /api/posts/{id}, DELETE /api/posts/{id} 는 인증이 필요하다.
- GET /api/posts, GET /api/posts/{id} 는 인증 없이 허용한다.
- Spring Security 설정을 적용한다.
- 인증 실패와 인가 실패 응답을 JSON 형태로 정리한다.

작업 규칙
- 이번 단계에서는 게시글 CRUD 구현 자체는 하지 마라.
- 필요한 보안 관련 코드만 추가 또는 수정해라.
- 기존 인증 흐름을 깨지 마라.

출력 방식
1. 변경 계획 요약
2. 코드 변경
3. 보안 흐름 설명
4. 생성/수정 파일 목록
```

```text

- 회원가입 성공 / 이메일 중복 실패
```
